# 运行底座与并行验收

复用现有TaskRunner、TaskScheduler、MonthlyExecutor、TaskJournal和package，没有增加另一套研究运行系统。正式任务的数据、候选、月份、种子、评分与排序规则不变。默认按CPU/可用内存自动选择1..8个外层进程，每任务1线程；允许显式指定workers。月份与候选独立派发，七目标在同一任务内共享设计并串行求解，避免内外层争抢。

## 实际修改

- runtime.py：以完整实现/数据/训练上下文身份为键，有界缓存全信息训练上下文、信息集视图及X/Xp矩阵。M限制视图继承同一金融列统计。缓存默认最多2个市场/任务/月上下文；模型权重不跨任务缓存。
- scheduling.py：Windows spawn进程池，最多2×workers在途任务，完成后补充；聚合始终按原输入顺序。进程生命周期及估计器内均限制数值库线程。每个物理fit使用操作系统租约、原子暂存/提交，别名保留共同尝试历史，成功产物缺失不得通过别名静默重拟合。
- artifacts.py：实际复现Windows byte-range锁下的pre-lock marker flush PermissionError，移除加锁前写标记，直接锁定空文件的第0字节。独立spawn/重复提交/去重/恢复压力测试连续8次通过（race_stress.json）。Windows官方允许锁定EOF以外的范围，见[LockFile文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfile)。
- TaskJournal：增量记录物理产物字节，避免每完成一项重新扫描全部记录；公共任务快照由协调进程写，worker只持有目标任务的记录。
- pipeline.py及模型错误路径：启动记录实际环境、代码和资源；失败区分数值、收敛、最优性、契约、I/O、用户中断与资源错误。保留worker traceback。所有已观察尝试用perf_counter计时，硬中断无法获知的调用数明确标记unknown，不能编造。
- reports.py：按物理尝试历史/求解续解计非负重试，成功与失败均有实际耗时；复用不算新训练。数值等价及小于0.1%相对损失效应单独标注，不改变原分数、排名或Bootstrap。core/full覆盖明确；没有生成虚构的Holm校正。

## 比较边界

cache_benchmark.json仅比较相同最终预处理/数据下的旧执行模式（重复transform）与身份校验后的矩阵命中；它是局部缓存基准，不能把其倍数称为完整实验加速。

real_technical.json执行同一24个真实月任务的serial与spawn并行版本，涵盖全指/沪深300初始窗口、全指2022-12，M/M+Z，分类强弱C和回归强弱alpha。记录冷启动与暖池、墙钟/CPU、各进程峰值RSS、缓存、成功率、模型保存加载、恢复不再拟合，以及逐任务预测/评分/候选排序一致性。峰值RSS是操作系统的各进程高水位，不冒充同时系统峰值。技术训练产物标为SMOKE_ONLY，临时权重和预测清理，不作为宏观效果证据。

原外部并行源码和第一轮逐fit产物缺失，不能声称复原旧8进程×2线程方案或核验每个旧fit。完整B+C未执行；实际总耗时还受后续扩展训练窗口、纯L1相关性、I/O及报告计算影响。不能用小任务倍数承诺整轮耗时或保证所有未来候选必定收敛。

最终实测数字随technical_acceptance.md及上述结构化证据一并交付。

## 最终实测

测机为Intel Core Ultra 5 225H、14逻辑CPU、33,820,106,752字节物理内存。使用Windows x64 Python3.11.9、锁定依赖，测试期间未同时运行其他计算验收。24项/模式全部成功，各96次估计器拟合，没有求解续解；两种模式共48项真实月任务、192次拟合。

| 同一任务集 | 串行1进程 | 并行4进程 |
|---|---:|---:|
| map墙钟秒（含冷启动及产物提交） | 43.6172 | 23.3322 |
| 首4项冷启动秒 | 8.7880 | 8.0638 |
| 其余20项暖池秒 | 34.8292 | 15.2684 |
| 成功任务 | 24/24 | 24/24 |
| 单求解进程峰值RSS MiB | 299.5 | 269.4—289.1 |
| 协调进程CPU秒 | 51.9063 | 12.5156 |

整体map提速1.8694倍，暖池部分2.2811倍。协调进程CPU窗口包括后续保存加载/恢复检查，worker的CPU字段为采样时累计进程时间；它们与map墙钟的计时边界不同，不能直接相除解释CPU利用率。峰值RSS不是同时系统总峰值。

两模式所有预测最大绝对差为0，评分通过rtol1e-10/atol1e-12比较，候选排名及排名哈希相同；保存加载预测逐元素完全相同，恢复时产物哈希/mtime不变，未重新拟合。强弱分类和七目标回归均通过原事前最优性阈值，最大分类截距残差0.000986582，小于0.001。

本小任务对照不包括所有正式月份/参数，不能外推整轮保证倍数。默认自动内存预算为每进程1.5GiB、另留2GiB系统余量，并最多8进程；实际采样窗口RSS更小，但正式运行仍保留资源余量。若需要改变worker，使用启动器参数，不改变候选、种子或求解线程。

额外纯L1一致性检查也通过：同一全指初始M/M+Z任务，串行33.0899秒、2进程29.6588秒，各14次拟合，预测和完整评分表完全相同，保存加载/恢复通过。两项任务耗时不均衡，不能期待两倍加速；正式月/候选批次使用动态补充队列分摊这种差异。

最终缓存局部基准：每轮12次相同上下文的X/Xp变换，重复3轮中位数0.825567秒；相同矩阵命中中位数0.0001214秒，矩阵完全相同。它验证重复变换成本确实消除，不代表整轮数千倍提速。正式搜索已有按月组织候选的顺序，可在有界LRU内复用同月矩阵。
